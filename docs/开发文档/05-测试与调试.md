# 测试与调试

`app` 插件还需覆盖 service 生命周期、能力交集、事件白名单、frontend 独立入口和窗口重开。Windows 手工验收需确认 service 崩溃不会退出宿主，关闭窗口不停止 service，停用时先关闭窗口再发送 shutdown。时间示例的数据来源是 Windows 系统时钟，未授予管理员权限。

## 1. 市场仓库校验

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\validate-market.ps1
```

该脚本会解析市场 JSON、校验 manifest 版本/id/type、原生 ABI 字段、frontend 路径、相对路径、可选 SHA-256 格式，并扫描 `artifacts` 中 ZIP 的绝对路径、`..`、反斜杠。通过时输出 `Market metadata and archive paths are valid.`。

## 2. 插件契约测试

每个插件在 `tests\contract.md` 中记录应覆盖的行为。至少测试 initialize、health、capabilities、工具调用、超时和大结果、JSON-RPC id/version 错误、工具名冲突、停用注销、sidecar 熔断、native ABI 架构与导出；frontend 还要测试 handshake、资源路径、能力白名单、配置 RPC、窗口状态/关闭、dispose 事件和关闭后重开。

Rust 示例可以先运行：

```powershell
Set-Location plugins\com.example.echo\src
cargo test
Set-Location ..\..\..
```

native 示例：

```powershell
Set-Location plugins\com.example.native-probe\src
cargo test
Set-Location ..\..\..
```

## 3. 宿主集成检查

```powershell
Set-Location E:\projectdata\PetAgent
cargo check --workspace
cargo test --workspace
npm test -- --run
npm run build
```

涉及 native-dll 或 Tauri 窗口时，还要启动桌面模式并手工确认；自动测试不能替代 DLL 加载和 WebView 视觉检查。

## 4. 常见错误定位

| 现象/错误 | 优先检查 |
|---|---|
| `manifest.json is required` | ZIP 根目录是否直接包含 manifest，而不是多套一层目录。 |
| `entry file ... is missing` | entry 路径是否相对、大小写和实际文件名是否一致。 |
| `requires PetAgent ...` | `petAgent` SemVer 范围是否覆盖宿主版本。 |
| `plugin does not target ...` | targets 是否包含 `windows-x64` 或 `windows-arm64`。 |
| `missing dependency` / `conflicts with` | 依赖已安装且版本满足，或移除冲突插件。 |
| sidecar `initialize returned null` | 响应 JSON 是否非 null、id 是否匹配、stdout 是否混入日志。 |
| sidecar `health check failed` | health 是否返回 `{ok:true}`，启动时依赖是否可用。 |
| provider 不生效 | `entry.serviceName` 是否允许，并通过 `llm.provider` 选择；不要只改 `plugins.enabled`。 |
| native `unsupported PE architecture` | DLL 目标架构是否与宿主一致。 |
| native `required export ... missing` | 五个导出名称和 C ABI 签名是否完全一致。 |
| frontend 403/404 | 插件是否 enabled、index 是否在 root 内、URL 是否含 `..` 或反斜杠；入口在 `dist/index.html` 时握手和 RPC 使用 `../__petagent/...`。 |
| frontend RPC 被拒绝 | 检查 `entry.frontend.capabilities`、协议版本和当前窗口是否仍属于该插件。 |
| 工具重复注册 | 让插件 ID 和 capability 名保持稳定；宿主会添加命名空间。 |

## 5. 日志和回滚策略

发布包中不要记录 API key、token 或完整用户文件内容。发生异常时，先停用插件；若更新后健康检查失败，使用市场页的回滚操作恢复上一版本，再重新启用。`market/security/revocations.json` 是人工下架公告，不是客户端自动阻断机制。
