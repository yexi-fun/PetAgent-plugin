# PetAgent 插件开发教程

## 1. 准备环境

插件仓库是独立开发仓库，目录为 `E:\projectdata\PetAgent-plugin`。宿主仓库 `E:\projectdata\PetAgent` 用于确认协议和做集成验证。

建议准备 Windows x64、Rust stable/cargo（MCP/native-dll 示例需要）、PowerShell 5+，以及可运行的 PetAgent 桌面构建。

```powershell
Set-Location E:\projectdata\PetAgent-plugin
```

## 2. 选择插件类型

| `type` | 适用场景 | 入口 | 进程边界 |
|---|---|---|---|
| `mcp` | 通过 MCP 暴露工具 | `entry.config` | MCP server 通常是独立 stdio/HTTP 进程 |
| `sidecar` | 自定义 JSON-RPC 工具服务 | `entry.executable` | 独立进程 |
| `provider` | 替换 LLM provider | `entry.executable` + `serviceName` | 独立进程，宿主适配为 `LlmService` |
| `native-dll` | 高性能原生工具 | `entry.library` + ABI 字段 | 宿主进程内加载 DLL |
| `frontend` | 独立 WebView 页面 | `entry.frontend` | 插件页面在宿主 WebView 中运行 |

第一次开发建议按目标类型选择模板：MCP 从 `plugins/com.example.echo` 开始；UI 插件从 `plugins/com.example.frontend` 开始。frontend 示例已经包含独立窗口入口、握手、配置 RPC、窗口关闭和 dispose 事件处理。

## 3. 创建插件目录

插件 ID 必须是小写、点号或连字符分隔的稳定标识，例如 `com.acme.weather`。不要在发布后修改 ID；宿主用它作为安装目录、工具命名空间和配置键。

```powershell
$id = "com.acme.weather"
New-Item -ItemType Directory -Force "plugins\$id\runtime" | Out-Null
New-Item -ItemType Directory -Force "plugins\$id\tests" | Out-Null
Copy-Item plugins\com.example.echo\LICENSE "plugins\$id\LICENSE"
Copy-Item plugins\com.example.echo\config.schema.json "plugins\$id\config.schema.json"
```

创建 `manifest.template.json`、`README.md` 和入口文件。所有包内路径使用 `/`，且必须是相对路径；不能写盘符、前导 `/`、`..` 或反斜杠。

## 4. 编写 Manifest

以 MCP 为例：

```json
{
  "schemaVersion": 1,
  "id": "com.acme.weather",
  "name": "Weather MCP",
  "version": "0.1.0",
  "apiVersion": 1,
  "petAgent": ">=0.1.0 <0.2.0",
  "type": "mcp",
  "description": "Expose weather lookup tools.",
  "entry": { "kind": "mcp", "config": "runtime/mcp.json" },
  "dependencies": [],
  "conflicts": [],
  "permissions": ["network"],
  "targets": ["windows-x64"],
  "configSchema": "config.schema.json"
}
```

`permissions` 要如实描述行为，但不会触发安装审批或运行时拦截。完整字段见 [Manifest 参考](./03-Manifest参考.md)。

## 5. 实现入口

### MCP

`runtime/mcp.json` 可以描述单个 server 或 `{ "servers": [...] }`：

```json
{
  "servers": [{
    "name": "weather",
    "transport": "stdio",
    "command": "runtime/windows-x64/weather.exe",
    "args": [],
    "env": {},
    "prefix": "weather__"
  }]
}
```

stdio 程序逐行读写 JSON-RPC 2.0。至少响应 `initialize`、`health`、`capabilities`、`tools/list`、`tools/call` 和 `shutdown`。宿主会把工具名规范化为 `<plugin_id>__<server>__<tool>`，避免与内建工具冲突。

### sidecar

```json
"type": "sidecar",
"entry": { "kind": "sidecar", "executable": "runtime/windows-x64/weather.exe" }
```

sidecar 必须实现 `initialize`、`health`、`capabilities`、`invoke`、`shutdown`。`capabilities` 返回能力名和 JSON Schema；非 provider 能力会注册为 `<plugin_id>__<capability>` 工具。

### provider

provider 与 sidecar 使用同一 JSON-RPC 进程，但必须声明：

```json
"type": "provider",
"entry": {
  "kind": "provider",
  "executable": "runtime/windows-x64/provider.exe",
  "serviceName": "llm",
  "serviceApiVersion": 1
}
```

当前允许的 service 名是 `llm`、`LlmService` 或 `pet.llm`。宿主用 `invoke` 调用 `llm.stream`，输入为 `messages` 和 `tools`，返回 `{ "chunks": [...] }`。每个 chunk 遵循宿主 `LlmChunk`：可含 `text`、`reasoning`、`tool_call`、`usage`。

### native-dll

native 插件必须声明 `abiVersion: 1`、`serviceName: "tools"`、`serviceApiVersion: 1`，并导出 ABI v1 的五个函数。详情见 [运行时协议](./04-运行时协议.md)。DLL 会在宿主进程内加载，开发者必须把崩溃和内存安全当作宿主级风险处理。

### frontend

```json
"type": "frontend",
"entry": {
  "kind": "frontend",
  "frontend": {
    "root": "dist",
    "index": "dist/index.html",
    "protocolVersion": 1,
    "capabilities": [
      "host-info",
      "config.read",
      "config.write",
      "window.close",
      "window.state",
      "notifications",
      "lifecycle-events"
    ],
    "window": {
      "title": "Weather",
      "width": 720,
      "height": 520,
      "minWidth": 420,
      "minHeight": 320,
      "resizable": true,
      "center": true
    }
  }
}
```

`index` 必须位于 `root` 内。`protocolVersion` 当前为 `1`；`capabilities` 必须只填写宿主支持且页面确实需要的能力。窗口尺寸会经过宿主上下限校验，当前宽度范围为 `420-1280`、高度范围为 `320-960`。

页面入口形如：

```text
pet-plugin://localhost/com.acme.weather/dist/index.html
```

入口在 `dist/index.html` 时，宿主接口使用 `../__petagent/` 相对路径。不要写成 `./__petagent/`，否则会请求到 `dist/__petagent/`：

```js
const protocolVersion = 1;

async function rpc(method, params = {}) {
  const response = await fetch(new URL("../__petagent/rpc", location.href), {
    method: "POST",
    headers: { "content-type": "application/json" },
    body: JSON.stringify({ protocolVersion, id: crypto.randomUUID(), method, params }),
  });
  const payload = await response.json();
  if (!response.ok || !payload.ok) {
    throw new Error(payload.error?.message || `RPC failed: ${response.status}`);
  }
  return payload.result;
}

const hostInfo = await fetch(
  new URL("../__petagent/host-info.json", location.href),
).then((response) => response.json());
const current = await rpc("config.get");
await rpc("config.set", { config: { theme: "dark" }, expectedRevision: current.revision });
await rpc("window.getState");

window.addEventListener("pet-plugin:event", (event) => {
  if (event.detail?.name === "pet-plugin-frontend-dispose") {
    // 停用、升级、卸载或宿主退出前清理页面资源。
  }
});

await rpc("window.close");
```

方法和 capability 的对应关系是：`host.getInfo` -> `host-info`，`config.get` -> `config.read`，`config.set` -> `config.write`，`window.getState` -> `window.state`，`window.close` -> `window.close`，`host.notify` -> `notifications`。未知方法或未声明能力会返回结构化错误。frontend 可以在自己的窗口内使用 HTML、Vue 或其他前端框架实现 modal，但不能动态注入宿主页面。

## 6. 本地构建和校验

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\validate-market.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\package-plugin.ps1 -PluginId com.example.echo
# UI 插件使用 frontend 示例或你的 frontend 插件 ID
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\package-plugin.ps1 -PluginId com.example.frontend
```

产物位于 `artifacts\<plugin-id>\<version>\`，其中 `payload\manifest.json` 是生成后的最终清单。打包脚本会计算 payload SHA-256 作为可选元数据，不生成签名。

> 当前 `package-plugin.ps1` 自动处理 `mcp`、`frontend`、`native-dll`。`sidecar` 和 `provider` 的宿主加载逻辑已存在，但发布前需要为二进制复制/构建增加对应打包分支，或手工准备同样结构的 `payload`。

## 7. 安装后的验收

1. 在 PetAgent 插件市场刷新索引并安装 ZIP。
2. 检查插件状态为已安装/未加载，然后启用插件。
3. 对 MCP/sidecar/native-dll 调用生成的工具；对 frontend 打开插件窗口；对 provider 切换 `llm.provider`。
4. 对 frontend 验证 handshake、`config.get/config.set`、`window.getState`、窗口内 modal，以及关闭窗口后从插件工具页重新打开。
5. 停用后确认工具注销、sidecar 退出、frontend 先收到 dispose 再关闭窗口。
6. 用同一版本更新失败时验证旧版本仍可回滚。
