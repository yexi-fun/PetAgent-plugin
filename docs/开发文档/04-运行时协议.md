# 运行时协议

## 1. 通用 JSON-RPC 约束

sidecar 和 MCP 都使用 stdin/stdout 逐行 JSON。请求和响应必须是 JSON-RPC 2.0，响应复用请求 `id`，单行最大 1 MiB。不要向 stdout 写日志；日志写 stderr。宿主 sidecar 默认启动超时 10 秒、调用超时 60 秒，连续崩溃 3 次后熔断。

## 2. sidecar 方法

### initialize

```json
{
  "pluginId": "com.acme.weather",
  "apiVersion": 1,
  "configuration": {}
}
```

返回非空 JSON；`configuration` 来自 `pluginConfig.<plugin-id>`。

### health

返回 `{ "ok": true, "message": "ready" }`。`ok=false` 会导致启用失败并记录 health 错误。

### capabilities

返回数组或 `{ "capabilities": [] }`：

```json
{
  "capabilities": [{
    "name": "weather.current",
    "description": "Get current weather.",
    "inputSchema": { "type": "object", "properties": {} }
  }]
}
```

普通 sidecar 能力会注册为 `<plugin_id>__weather_current`（非字母数字字符规范化为 `_`）。

### invoke

普通能力请求：

```json
{
  "capability": "weather.current",
  "input": { "city": "Shanghai" }
}
```

### shutdown

收到后释放资源；宿主等待最多 2 秒，超时会结束进程。

## 3. provider 的 `llm.stream`

provider 仍实现上述 sidecar 生命周期，但宿主会调用：

```json
{
  "capability": "llm.stream",
  "input": {
    "messages": [{ "role": "user", "content": "hello" }],
    "tools": []
  }
}
```

返回 `{ "chunks": [...] }` 或直接返回 chunk 数组。chunk 与宿主 `pet-core` 的 `LlmChunk` 对齐，可含 `text`、`reasoning`、`tool_call`、`usage`。

provider 通过 initialize/health 后才替换当前 `SwitchableLlm`；同一 `serviceName` 同时只能有一个第三方 provider。provider 不是普通 `plugins.enabled` 开关，而是由宿主 `llm.provider` 配置驱动。

## 4. native-dll ABI v1

必须导出以下 C ABI 函数：

```c
uint32_t pet_plugin_api_version(void);
int32_t pet_plugin_init(const PetHostApi* host, PetPluginHandle* out);
int32_t pet_plugin_call(PetPluginHandle handle, const uint8_t* input, uint64_t len, PetBuffer* out);
void pet_plugin_shutdown(PetPluginHandle handle);
void pet_plugin_free_buffer(PetBuffer* buffer);
```

`PetHostApi` 包含 `struct_size` 和 `api_version`；`PetBuffer` 是指针加长度。跨边界只能传固定宽度整数、指针、长度和 UTF-8 JSON 字节，不能传 Rust trait、`String`、`Vec` 或跨 allocator 所有权。

宿主顺序是：PE 架构预检 -> LoadLibrary -> 查找五个导出 -> ABI 版本 -> init -> `{"method":"health"}`。不要求 Authenticode 或 manifest 签名；调用输入和输出均不超过 1 MiB。

## 5. frontend URI 协议

页面入口形如 `pet-plugin://localhost/com.example.frontend/dist/index.html`。宿主只为 enabled 的 frontend 插件提供资源。路径会拒绝编码百分号、反斜杠、绝对路径、`..` 和逃出 `entry.frontend.root` 的文件。

页面入口位于 `dist/index.html` 时，应请求 `../__petagent/host-info.json`，返回 `pluginId`、`pluginApiVersion`、`frontendProtocolVersion`、`sessionId` 和协商后的 capabilities。页面还可向 `../__petagent/rpc` 发送受 manifest 能力白名单限制的 JSON 请求，当前方法包括 `host.getInfo`、`config.get`、`config.set`、`window.getState`、`window.close` 和 `host.notify`。窗口关闭或停用时宿主发送 `pet:plugin-frontend-dispose` 并关闭窗口。该协议不提供任意 Tauri command、文件系统、Shell 或进程启动能力。
